# Evidence and public release

## Allowed
Generic methodologies, blank templates, original explanations and synthetic scenarios created without company artifacts. Use invented names and example.invalid URLs. State which parts were simulated and what was not tested.

## Excluded
Company code, repository extracts, exact vulnerabilities, internal paths/architecture, business data, customer or staff identifiers, secrets, real logs and screenshots. Public availability of a repository is not permission to republish security findings.

## Release gate
- Confirm ownership and explicit release approval where needed.
- Recreate demonstrations from scratch rather than lightly redacting real evidence.
- Check text, filenames, Git diff, images and metadata.
- Ensure outcomes and skills claims have evidence and no simulated result is presented as production experience.
- Record reviewer/date and approve only the intended artifact/version.

Private academy storage does not relax these restrictions.
